# Pendientes de UX / Correcciones Visuales

Este documento recopila las observaciones y ajustes visuales detectados durante las pruebas manuales del Frontend para ser resueltos en futuras iteraciones.

## Mejoras y Correcciones Detectadas:
*(A la espera de los comentarios de la prueba)*
1. **Landing Page (Hero):** Eliminar el panel de 'Buscar alumno'. Actualmente no tiene sentido de negocio porque el sistema es exclusivo para administrativos y requiere autenticación. Reemplazar por un mensaje de bienvenida limpio y un botón central destacado de 'Ingresar al Sistema' (CTA al Login).
2. **Navegación en el Login:** Falta un botón o enlace para regresar a la página de inicio (Landing). Práctica recomendada: hacer que el Logo del ITEC en la pantalla de login sea clickeable y redirija a la raíz ('/'), o agregar un pequeño enlace discreto de 'Volver al Inicio'.
3. **Dashboard (Datos Mockeados):** La pantalla principal muestra KPIs y gráficos con datos ficticios. Dado que el Backend no expone aún un endpoint de métricas o estadísticas reales, se debe decidir si: a) Ocultar estas tarjetas temporalmente para no confundir al usuario, o b) Desarrollar un endpoint real (/api/core/dashboard/metricas) en el backend para poblar esto con la cantidad real de alumnos, profesores y comisiones activas.

4. **Elementos del Sidebar Inactivos:** El menú lateral muestra secciones como 'Materias', 'Reportes', 'Certificados' y 'Configuración'. Estas secciones fueron maquetadas en la Fase 3 pero aún no tienen un desarrollo real en el frontend ni consumen APIs. **Acción:** Ocultar estos ítems del menú temporalmente hasta que se desarrollen sus respectivos módulos para evitar confusión.
5. **Gestión de Administradores:** Actualmente no existe una pantalla en el frontend para crear o gestionar usuarios con rol 'ADMIN' o 'ADMINISTRATIVO'. La única cuenta existente (dmin) fue creada por el \DatabaseSeeder\ de desarrollo. **Acción:** Crear un módulo de 'Gestión de Usuarios' (solo visible para superusuarios) en la próxima iteración.

6. **Bug de Navegación y 401 en CSR:** Al hacer clic en 'Alumnos' desde el Dashboard, el cliente HTTP recibe un 401 Unauthorized desde el backend y fuerza el cierre de sesión ('Sesión expirada'). Posible causa: El cliente Axios/Fetch (pi-client.ts) no está adjuntando correctamente el Token JWT durante la navegación en el cliente (Client-Side Rendering), o hay una discrepancia entre dónde se guarda el token (Cookies vs LocalStorage) y de dónde lo lee el interceptor.
7. **Errores 404 en Consola (Prefetch):** Next.js intenta hacer prefetch en background de las páginas inactivas del menú lateral ('Materias', 'Reportes', etc.), generando errores 404 en la consola (ej. certificados?_rsc=...). Esto se solucionará cuando se aplique el Punto 4 (ocultar enlaces inactivos o desactivar su prefetch).

8. **Claridad en Formulario de Profesor (Teléfonos):** El formulario solicita 'Teléfono' y luego 'Teléfono de Contacto'. Esto se debe a que la BD almacena un teléfono en la tabla 'Usuario' y otro en 'Profesor'. **Acción:** Mejorar la UX en el Frontend renombrando las etiquetas (Labels) para que sean claras (ej. 'Teléfono Personal' y 'Teléfono Secundario / Emergencias') o unificando el campo si no hay necesidad real de tener dos.

9. **Impacto Crítico del Bug 401 (Pérdida de Datos):** El error 401 de Sesión Expirada (Punto 6) no solo ocurre al listar (GET), sino también al guardar datos (ej. POST crear Profesor). Como el cliente no envía el Token, el Backend rechaza la petición con 401 ANTES de guardar en MySQL, y el Frontend redirige al login sin mostrar el error real. **Resultado:** Los datos ingresados se pierden y el actor no se crea. **Acción Urgente:** Corregir la inyección del Token Bearer en Axios/Fetch para peticiones de componentes cliente.
