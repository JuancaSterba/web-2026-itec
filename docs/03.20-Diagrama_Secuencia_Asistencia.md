# Diagrama de Secuencia: Asistencia y Regularidad (70 %)

> Reescrito 2026-10-07 con lo implementado en [`specs/002-regularidad-asistencia`](../specs/002-regularidad-asistencia/spec.md) (US-ASIS-02, US-REP-01, anexo US-ASIS-03/05). Reemplaza el diseño anterior, en el que `ms-asistencias` notificaba "Libre" al Core en cada carga: nunca se implementó.

## Reglas
- **Porcentaje** = clases en que el alumno estuvo presente ÷ sus clases con marca × 100. La **tardanza cuenta como presente**. Las fechas en que el alumno no tiene marca (por ejemplo, se inscribió después) no cuentan en su total.
- **REGULAR** con 70 % o más; **NO_REGULAR** por debajo; **SIN_REGISTROS** si no tiene ninguna clase con marca. Se compara sin redondear (70 % exacto es regular).
- El cálculo vive en `ms-asistencias` (`ResumenAsistenciaCalculator`), el dueño de los datos; el resto del sistema consume el resumen.
- La asistencia afecta la condición **solo al cerrar la cursada**: NO_REGULAR deja LIBRE cualquiera sea el promedio; REGULAR sigue la regla de parciales. Una cursada cerrada no se recalcula.

## 1. Registro y consulta del porcentaje

```mermaid
sequenceDiagram
    autonumber
    actor Docente
    participant Next as Next.js (servidor)
    participant Gateway as API Gateway
    participant MS as ms-asistencias

    Docente->>Next: Toma asistencia de la comisión (presente / ausente / tardanza)
    Next->>Gateway: POST o PUT /api/v1/asistencias (una por alumno)
    Gateway->>MS: POST /api/asistencias (X-User-Roles)
    MS-->>Gateway: 201 Created
    Gateway-->>Next: 201 Created

    Docente->>Next: Abre la vista de comisión, el reporte o la ficha del alumno
    Next->>Gateway: GET /api/v1/asistencias/resumen?cursadaIds=1,2,3
    Gateway->>MS: GET /api/asistencias/resumen?cursadaIds=1,2,3
    MS->>MS: ResumenAsistenciaCalculator por cursada
    MS-->>Gateway: 200 [cursadaId, presentes, tardanzas, ausentes, totalClases, porcentaje, estado]
    Gateway-->>Next: 200
    Next-->>Docente: Porcentaje y badge Regular / No regular / Sin registros
```

## 2. Cierre de cursada con regularidad

```mermaid
sequenceDiagram
    autonumber
    actor Usuario as Administrativo / Admin
    participant Next as Next.js (servidor)
    participant Core as Backend Core
    participant MSA as ms-asistencias
    participant MSN as ms-notas

    Usuario->>Next: "Cerrar cursada"
    Next->>Core: GET /api/v1/cursadas/{id}/condicion-preview (vía Gateway)
    Core->>MSA: GET /api/asistencias/resumen?cursadaIds={id} (X-User-Roles: ADMIN)

    alt ms-asistencias no responde
        Core-->>Next: 503 "No se pudieron obtener las asistencias…"
    else SIN_REGISTROS
        Core-->>Next: 400 "No hay asistencias registradas para este alumno en la comisión"
    else NO_REGULAR
        Core->>MSN: GET parciales de la cursada
        Core-->>Next: LIBRE, motivoLibre = ASISTENCIA
    else REGULAR
        Core->>MSN: GET parciales de la cursada (deben ser 3)
        Core-->>Next: Condición por promedio (motivoLibre = PROMEDIO si queda LIBRE)
    end

    Next-->>Usuario: Diálogo con asistencia, promedio, condición y motivo
    Usuario->>Next: Confirma
    Next->>Core: POST /api/v1/cursadas/{id}/cerrar
    alt Cursada ya cerrada
        Core-->>Next: 409 "La cursada ya está cerrada"
    else Abierta
        Core->>Core: Recalcula y guarda condicionFinal y notaCierre
        Core-->>Next: 200
    end
```

## Consideraciones
- **Comunicación interservicio:** el Core consulta a `ms-asistencias` por HTTP (C1.4, C4.1); no lee su base. Suma acoplamiento sincrónico: ver deuda #22 en [`pendientes.md`](./pendientes.md).
- **Permisos:** el endpoint de resumen exige ADMIN, ADMINISTRATIVO o PROFESOR. Que un profesor vea solo sus comisiones se controla en los Server Components de Next (deuda #42).
- **Fuera de alcance:** inasistencias justificadas (US-ASIS-04) y bloquear la edición de asistencias después del cierre (parte de US-ASIS-05).
